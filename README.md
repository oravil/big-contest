# Big Shawerma — Contest Prize Redemption System

> **خليك مع الكبير / انت الاهم**
> Stay With The Big — You Matter
> Branches: شربين (Sharbeen) | بلقاس (Belqas)

A full-stack Arabic RTL web application for Big Shawerma's contest prize
redemption. Public winners hall + password-gated staff redemption flow.
JSON file storage, no database, no Firebase, no external auth.

---

## Tech stack

| Layer    | Technology                                      |
| -------- | ----------------------------------------------- |
| Frontend | React 18 + Vite, TailwindCSS v3, React Router 6 |
| Backend  | Node.js 20 + Express                            |
| Storage  | `backend/data/winners.json` (flat JSON file)    |
| Font     | Cairo (Google Fonts) — 400 / 600 / 700 / 900    |
| Auth     | Plain team password matching (no JWT, no sessions) |
| Locale   | Arabic RTL (`<html lang="ar" dir="rtl">`)       |
| Timezone | `Africa/Cairo` for all human-readable timestamps |

## Setup

### Prerequisites

- **Node.js ≥ 20**
- npm

### 1. Install root dependencies (Express + tooling)

```bash
npm install
```

### 2. Install frontend dependencies

The frontend is a separate Vite app with its own `package.json`. From the
project root:

```bash
npm run frontend:install
```

…or directly:

```bash
cd frontend && npm install
```

The frontend `package.json` should declare:

- **dependencies:** `react`, `react-dom`, `react-router-dom`
- **devDependencies:** `vite`, `@vitejs/plugin-react`, `tailwindcss`,
  `postcss`, `autoprefixer`

A minimal `frontend/postcss.config.js` is also required:

```js
module.exports = {
  plugins: { tailwindcss: {}, autoprefixer: {} },
};
```

…and `frontend/src/main.jsx`:

```jsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import App from './App';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')).render(<App />);
```

### 3. Seed the data file

Generates 7 winners with unique `BIG-XXX-0000` codes →
`backend/data/winners.json`.

```bash
npm run seed
```

> **Re-running** `npm run seed` regenerates the file and **overwrites**
> any prior redemption history. Only run it for a fresh start.

## API reference

All requests/responses are JSON. Errors return Arabic messages.

### `GET /api/health`

```json
{ "status": "ok", "timestamp": "2025-..." }
```

### `GET /api/winners` — public

Returns the contest metadata and the public winners list. The `code` field
is stripped from each winner; the `teams` object is never sent.
Auto-expires winners whose `expiry_date` is past (Africa/Cairo).

```json
{
  "contest": { "name_ar": "...", "active": true, ... },
  "winners": [
    { "id": "W001", "name_ar": "...", "status": "active", ... }
  ]
}
```

### `POST /api/lookup`

Body:

```json
{ "code": "BIG-WNR-4821", "password": "BIG_WA_2025" }
```

Behavior:

1. Validates password against teams.
2. Normalizes code (`trim().toUpperCase()`).
3. Returns the matched winner (without `code`); does **not** mutate status.

Status codes:

- `200` — `{ winner: { ... } }`
- `400` — `{ error: "الكود مطلوب" }`
- `401` — `{ error: "كلمة المرور غير صحيحة" }`
- `404` — `{ error: "الكود غير موجود" }`

### `POST /api/redeem`

Body: same as `/api/lookup`.

1. Validates password; resolves team identity.
2. Auto-expires; rejects non-active winners.
3. On `active`: marks `redeemed`, writes `winners.json` atomically,
   returns the redemption details.

Status codes:

- `200` — `{ success: true, winner: { ... } }`
- `400` — `{ error: "الكود مطلوب" }`
- `401` — `{ error: "كلمة المرور غير صحيحة" }`
- `404` — `{ error: "الكود غير موجود" }`
- `409` — `{ error: "تم تسليم هذه الجائزة مسبقاً" }`
- `410` — `{ error: "انتهت صلاحية هذه الجائزة" }`

## Production build

```bash
# 1. Build the frontend (outputs to frontend/dist)
npm run build

# 2. Start the API in production mode (serves dist/ statically)
npm run start
```

Required env vars in production:

| Variable       | Example                              | Notes                              |
| -------------- | ------------------------------------ | ---------------------------------- |
| `PORT`         | `3001`                               | Set by most hosts automatically.   |
| `NODE_ENV`     | `production`                         | Required for static + CORS rules.  |
| `DATA_PATH`    | `/data/winners.json`                 | Persistent volume mount path.      |
| `FRONTEND_URL` | `https://your-domain.com`            | CORS allow-list (single origin).   |

The frontend reads `VITE_API_URL` at build time. Set it to your backend's
`/api` URL when deploying the SPA separately (e.g. GitHub Pages).

## Deployment

### Option A — Single-host (recommended)

Deploy the Express server on a Node host (Railway / Render / Fly.io free
tiers all work). The same Express process serves the built SPA from
`frontend/dist`. Mount a persistent volume and point `DATA_PATH` at
`/data/winners.json`.

Initial seed (one-time, on the server volume):

```bash
DATA_PATH=/data/winners.json node scripts/seed.js
```

### Option B — GitHub Pages frontend + separate backend

1. In `frontend/vite.config.js`, set `base: '/<repo-name>/'`.
2. Build with `VITE_API_URL=https://<your-backend>/api npm run build`.
3. Deploy `frontend/dist` to the `gh-pages` branch.
4. Deploy the backend separately (Railway/Render/Fly.io).
5. Set `FRONTEND_URL=https://<user>.github.io` on the backend so CORS
   accepts requests from the Pages origin.

> **Important:** never commit `winners.json` to a public repository — it
> contains team passwords. Treat it as production data only.

## Operational notes

- **Backups.** The data store is a single file. Snapshot it on a schedule
  (cron + `cp`, or a host-managed volume snapshot).
- **Single source of truth.** The backend is authoritative for status.
  The frontend never decides whether a code is valid/redeemed/expired.
- **Auto-expire.** Performed on every read of `/api/winners`,
  `/api/lookup`, and `/api/redeem` using Africa/Cairo today.
- **No persistence on the client.** Refreshing the staff page logs the
  team out by design — there is no `localStorage` / `sessionStorage` /
  cookie storage anywhere in the app.
- **Password rotation.** Edit `winners.json` directly to rotate team
  passwords; restart not required (file is re-read on each request).
